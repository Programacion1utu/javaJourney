Base de datos
-- Cuentas de estudiantes (creadas por la docente)
CREATE TABLE students (
  id            SERIAL PRIMARY KEY,
  nombre        VARCHAR(100) NOT NULL,
  apellido      VARCHAR(100) NOT NULL,
  grupo         VARCHAR(50)  NOT NULL,
  password_hash VARCHAR(64)  NOT NULL,  -- SHA-256 de la contraseña
  created_at    TIMESTAMP DEFAULT NOW(),
  last_access   TIMESTAMP
);

-- Progreso por lección
CREATE TABLE lesson_progress (
  student_id   INT REFERENCES students(id) ON DELETE CASCADE,
  lesson_id    INT NOT NULL,
  completed_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY(student_id, lesson_id)
);

-- Progreso por quiz
CREATE TABLE quiz_progress (
  student_id   INT REFERENCES students(id) ON DELETE CASCADE,
  topic_id     INT NOT NULL,
  score        INT,
  completed_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY(student_id, topic_id)
);

-- Configuración global (temas habilitados)
CREATE TABLE config (
  key   VARCHAR(50) PRIMARY KEY,
  value JSONB
);
-- Valor inicial: INSERT INTO config VALUES ('enabled_topics', '[1]');

ON DELETE CASCADE — cuando la docente elimina un estudiante, su progreso se borra automáticamente de todas las tablas. No quedan registros huérfanos.

API endpoints

Autenticación

POST
/api/auth/student
Recibe { nombre, apellido, password } → verifica en DB → devuelve JWT de estudiante (24 h).
POST
/api/auth/teacher
Recibe contraseña → verifica hash en variable de entorno → devuelve JWT docente.

Estudiante (requiere JWT estudiante)

GET
/api/student/progress
Devuelve lecciones y quizzes completados del estudiante autenticado.
POST
/api/verify
Recibe { lessonId, output } → compara server-side con EXPECTED_OUTPUTS → devuelve { correct } y guarda progreso si es correcto.
POST
/api/quiz/complete
Valida respuestas del quiz server-side y guarda el resultado.

Docente — gestión de estudiantes (requiere JWT docente)

GET
/api/teacher/students
Lista todos los estudiantes con su progreso (lecciones, quizzes, último acceso).
POST
/api/teacher/students
Crea una cuenta. Recibe { nombre, apellido, grupo, password }. La docente define la contraseña inicial.
PUT
/api/teacher/students/:id/password
Resetea la contraseña de un estudiante (si la olvidó).
DELETE
/api/teacher/students/:id
Elimina estudiante y todo su progreso (CASCADE).
PUT
/api/teacher/topics
Actualiza temas habilitados. Efecto inmediato para todos los estudiantes.

Pública

GET
/api/config
Devuelve temas habilitados. El frontend la consulta al cargar para mostrar u ocultar temas en el sidebar.

Seguridad
ElementoHoyCon Vercel
Contraseña docente Hash en JS obfuscado — reversible Variable de entorno Vercel — nunca en el cliente
Contraseñas de estudiantes No existen Hash SHA-256 en DB — nunca en texto plano
EXPECTED_OUTPUTS Visibles en el JS del navegador Solo en el servidor — el cliente nunca los ve
Verificación de output Client-side — manipulable con DevTools Server-side — no manipulable
Progreso localStorage — manipulable DB verificada con JWT — confiable
Temas habilitados Solo en el navegador de la docente DB → efecto global instantáneo
Orden de implementación
1
Crear proyecto Vercel + base de datos Neon ~20 min
Ambos gratuitos. Conectar Neon a Vercel como variable de entorno DATABASE_URL.
2
Crear tablas y endpoint /api/config ~30 min
El frontend consulta los temas habilitados desde el servidor en lugar de localStorage.
3
Auth de estudiantes: crear cuentas y login ~2 h
Panel docente para crear/eliminar/resetear cuentas. Pantalla de login para estudiantes. JWT de sesión.
4
Verificación server-side ~1 h
Mover EXPECTED_OUTPUTS al servidor. El cliente llama a /api/verify: solo recibe "correcto / incorrecto", nunca la salida esperada.
5
Dashboard de progreso en tiempo real ~1 h
Tabla de estudiantes con lecciones, quizzes y último acceso. La docente ve quién avanzó y quién no.
6
Quizzes server-side ~1 h
Respuestas correctas en el servidor. El cliente solo envía las respuestas del estudiante.
Variables de entorno
# Configurar en el panel de Vercel — nunca en el código

JWT_SECRET="cadena-aleatoria-de-32-chars+"    # firma los tokens
TEACHER_PASSWORD_HASH="sha256..."          # contraseña docente hasheada

Cambiar la contraseña docente = editar una variable en el panel de Vercel. Sin tocar código, sin regenerar el archivo ofuscado.
